# 장애와 복구

`/?view=admin` 또는 `/연동상태`에서 pending/running/failed/review 작업과 미확인 effects를 확인합니다. 일반 사용자는 관리자 API를 사용할 수 없습니다. 프로젝트를 일시 정지하려면 설정의 `enabled:false`를 D1에 적용합니다. 이는 새 작업 실행을 멈추며 기존 투표의 시간 기반 마감과 결과 조회는 유지합니다.

## 상태 의미

| 상태    | 뜻                                 | 다음 행동                          |
| ------- | ---------------------------------- | ---------------------------------- |
| pending | 다음 실행 시각을 기다림            | Cron 또는 관리자 1단계 실행        |
| running | lease를 획득해 실행 중             | 강제 종료면 3분 뒤 재획득          |
| done    | 해당 작업 완료 또는 DM 불가로 종료 | 필요한 경우 state의 skip 이유 확인 |
| failed  | 권한/설정 오류 또는 재시도 소진    | 원인 수정 후 관리자 재시도         |
| review  | 생성의 실제 성공 여부 불명확       | 원격 리소스 확인 후 복구           |

재시도는 429의 Retry-After와 지수 backoff를 함께 적용하며 단계당 최대 8회입니다. Notion 생성 결과가 불확실하면 즉시 `review`로 멈추고 자동 재생성하지 않습니다. 명시적 429 거절은 Retry-After에 따라 재시도할 수 있습니다. Discord 생성 결과는 몇 차례 조회로 확인하고 `review`로 멈춥니다. DM 거부/사용자 탈퇴는 해당 작업만 끝냅니다.

## 외부 생성의 불확실성

Notion/Discord/D1 사이에는 분산 트랜잭션이 없습니다. 정확히 한 번 생성이라는 보장을 주장하지 않습니다. 앱은 먼저 `effects.state=sending`을 기록하고 POST합니다. 재시작 시 sending이면 생성 POST를 반복하지 않습니다.

- Notion: 생성 요청은 최대 5초. 성공 결과나 연결된 페이지 ID가 D1에 남아 있으면 재사용합니다. 기록이 없으면 제목/시간으로 자동 추정하지 않고 즉시 수동 확인으로 전환합니다. Notion 요청 ID 속성은 사용하지 않습니다. D1의 작업 ID와 `issue_links.request_id`는 같은 요청의 재클릭 및 단계 복구를 위해 유지하는 내부 식별자입니다.
- Discord 메시지: 고정 nonce와 enforce_nonce, 본문의 고유 표식으로 조회합니다. 조회 범위는 최근 100개입니다.
- 포럼: 이름의 고유 표식으로 활성 스레드와 최근 보관 100개를 조회합니다.
- 텍스트 채널 스레드: 원래 메시지 ID와 같은 thread ID로 조회합니다.

조회 범위 밖의 메시지가 있거나 eventual consistency 때문에 보이지 않으면 **없다고 단정하여 다시 생성하지 않습니다**. Discord에 대한 관리자 재시도는 같은 조회를 다시 실행합니다. 불명확한 Notion 생성은 관리자 재시도 버튼을 눌러도 POST를 다시 보내지 않습니다. 불명확한 효과를 단순 삭제하면 중복 생성될 수 있습니다.

## 수동 결과 확정

1. 먼저 `enabled:false`로 중단하고 D1 export를 만듭니다. 작업 payload와 `effects.id`를 확인하되 토큰을 공유 로그에 남기지 않습니다.
2. Notion에서는 작업 payload의 제목·담당자·내용·생성 일시를 운영자가 대조하고 실제 페이지를 확인합니다. 같은 제목의 다른 이슈를 자동 연결하지 않습니다. Discord는 표식과 생성 일시·채널을 대조합니다.
3. 이미 생성되었으나 검색 범위 밖이라면 권한 있는 D1 콘솔에서 해당 effect의 `state='done'`, `result`에 어댑터가 사용하는 최소 JSON을 기록합니다. 페이지/일반 메시지는 `{"id":"실제ID"}`, 포럼은 `{"id":"스레드ID","message":{"id":"첫메시지ID"}}`, 텍스트 스레드는 `{"id":"스레드ID"}`입니다. 이 값은 실제 API로 확인한 값이어야 합니다.
4. **생성이 발생하지 않았음이 확실한 경우에만** 해당 effect 행을 제거합니다. 그러면 다음 실행에서 생성 POST가 가능합니다. 조회 결과가 단순히 없다는 것만으로 확정하지 마세요.
5. 설정을 다시 켜고 관리자 화면에서 작업을 재시도합니다. 진행 state에 page/thread가 없다면 완료 effect의 결과를 읽어 연결을 보충합니다.

Notion 성공 뒤 Discord 실패는 같은 Notion 페이지를 유지합니다. 담당자 권한 상실이나 연결 만료로 멈추면 본인이 연결을 갱신한 다음 기존 작업을 재시도합니다. 원래 요청을 취소하고 새 요청을 만드는 경우 기존 Notion 작업과 중복되지 않도록 운영자가 확인합니다.

## Webhook과 스레드 복구

같은 이벤트 ID는 작업 하나만 등록됩니다. 순서가 뒤바뀌어도 최신 페이지를 다시 조회합니다. 원본 페이지가 404면 삭제와 권한 상실을 구별하지 않고 **삭제 또는 접근 불가**로 표시하며 기록을 지우지 않습니다.

자동 보관된 스레드는 갱신·메시지 전송 동안 열고 원래 보관 상태로 되돌립니다. 이 과정에는 Manage Threads 권한이 필요합니다. 외부 API 실패가 원래 상태 복구와 겹치면 스레드가 열린 상태로 남을 수 있으므로 운영자가 확인합니다. 잠긴 스레드와 실제 API 권한은 실환경 검증 항목입니다.

Webhook 전송 자체를 놓친 경우 관리자 D1 콘솔에서 해당 연결된 page ID만 대상으로 `issue-sync` 작업을 수동 등록할 수 있습니다. 임의로 전체 Notion DB를 짧은 주기로 재조회하지 않습니다.

```sql
-- 실제 확인한 page ID와 고유한 복구 작업 ID로 바꾸세요.
INSERT OR IGNORE INTO jobs(id,kind,payload,next_at,created_at)
VALUES('manual-sync:고유식별자','issue-sync','{"pageId":"확인한-page-id"}',0,0);
```

## 무료 한도 초과 및 긴 장애

1. Free 플랜을 유지합니다. 자동 업그레이드는 하지 않습니다. 반복 오류를 멈추려면 프로젝트를 비활성화합니다.
2. CPU 초과이면 한 단계의 페이지 크기를 줄이고 관련 테스트를 실행합니다. D1 한도이면 읽기/쓰기 지표와 인덱스를 확인합니다. 요청 한도이면 다음 갱신 시각까지 기다립니다.
3. 플랫폼 가용성이 돌아오면 활성화 후 관리자 1단계 실행 또는 Cron으로 재개합니다. lease 만료 작업은 재획득합니다. failed/review는 자동 무한 반복하지 않으므로 원인을 확인하고 재시도합니다.
4. 스케줄 커서는 한 주씩 따라잡습니다. 이미 발행된 보고/결과는 고유 ID로 재생성되지 않습니다. 놓친 개시가 투표 마감 이후라면 과거 명단을 만들지 않고 실패로 남깁니다. 오래된 미투표 DM은 보내지 않습니다.
5. 과거 보고를 뒤늦게 최초 수집하면 **원래 월요일 시점의 Notion 상태를 재현할 수 없습니다**. 보고 week는 예정 주차이고, 데이터는 실제 복구 조회 시점의 상태입니다. 정확한 역사 보고가 필요하면 Notion 별도 버전 보관을 확장해야 합니다.

## 백업과 정리

```sh
npx wrangler d1 export project-manager --remote --output work/backup.sql
```

백업에는 사용자 ID·투표가 있으므로 비공개로 보관하고 Git에 커밋하지 않습니다. 복구는 새 D1에 검증한 export를 적용하고 binding을 전환하는 방식이 안전합니다. Free Time Travel 기간은 7일이므로 장기 백업을 대체하지 않습니다.

만료 인증 데이터만 정리하는 예시입니다. 먼저 `SELECT COUNT(*)`로 건수를 확인하고 큰 데이터는 작은 batch로 나누세요. 주차 보고, 이슈 연결, 작업 효과는 중복 방지와 결과 조회에 쓰이므로 임의 삭제하지 않습니다.

```sql
DELETE FROM oauth_states WHERE expires < unixepoch()*1000;
DELETE FROM sessions WHERE expires < unixepoch()*1000;
DELETE FROM challenges WHERE expires < (unixepoch()-86400)*1000;
DELETE FROM drafts WHERE expires < (unixepoch()-86400)*1000;
```

로그에는 원본 요청, OAuth code/token, Bot Token, Notion Token, 댓글 코드, 전체 오류 응답을 출력하지 않습니다. 코드의 오류 기록은 서비스명/HTTP 상태 또는 정제된 앱 오류입니다. 기본 Workers observability는 꺼져 있습니다. 운영에서 로그를 켤 때 요청 URL(query에 OAuth code가 있을 수 있음)과 헤더 수집 정책을 먼저 확인하세요.
