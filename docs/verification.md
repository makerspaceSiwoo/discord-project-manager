## 화면 변경 반영

- 사용자가 요청한 검은 배경과 Discord 계열 보라색 테마.
- 기본 탭은 **팀원이 선택한 시간**. 각 칸에 참석 가능 인원 수와 색상 농도 표시.
- 모든 가능한 시간을 보여주며, 다수 또는 전원 참석 기준으로 시간을 결정하거나 추천하지 않음.
- 주차 표시: `2026-11-09 ~ 2026-11-15`처럼 월~일 날짜 범위.
- 요일 헤더를 별도 sticky 행으로 분리하고 스크롤 컨테이너 상단 여백 제거.
- 모바일 너비에서 가로 넘침은 시간표 내부 스크롤에 한정. 팀 시간 칸을 누르면 작은 화면에서 인원 상세를 하단 패널로 표시.
- 실제 터치 기기의 Safari/Chrome 조합, 스크린리더 전체 탐색, 데스크톱의 모든 너비는 검증하지 않음. Pointer Events와 키보드 지원 구현을 실제 기기 검증과 혼동하지 않음.

## 현재 한계

1. 개인 Notion OAuth 경로는 구현하지 않았습니다. 게스트 댓글 대안은 실제 검증 기록을 요구하며 기본 비활성입니다. 게스트 인증이 성공했다고 표시하지 않습니다.
2. Notion의 페이지별 게스트 접근 철회를 자동으로 즉시 완전히 탐지하지 않습니다. 관리자 철회, 만료·재인증, API 실패 중단을 사용합니다. People 지정 가능 여부와 실제 업무 페이지 열람 권한은 별개입니다.
3. 외부 API 결과가 불명확하면 안전하게 review로 멈춥니다. 모든 장애에서 사용자 개입 없이 exactly-once 복구를 보장하지 않습니다. 최근 메시지/스레드 검색 범위 밖은 관리자 확인이 필요합니다.
4. 한 번에 작업 단계 하나만 실행해 무료 CPU 부담을 줄였습니다. 이슈 생성·담당자 알림·보고 전체 게시까지 여러 분이 걸릴 수 있습니다. 보고 100개는 약 105분 이상입니다. 정확한 정시 완료는 보장하지 않습니다.
5. Notion 상세 설명은 첫 25개 최상위 텍스트 블록의 700자 요약입니다. 긴 본문·중첩 블록·첨부의 전체 표현은 원문 링크에서 확인합니다.
6. 보고 스냅샷은 조회하는 기간의 데이터이며 Notion의 원자적 역사 스냅샷이 아닙니다. 장애 뒤 최초 수집으로 과거 상태를 복원할 수는 없습니다.
7. 초기 한 Worker는 `PROJECT_ID` 한 프로젝트를 실행합니다. 다중 팀 서비스, 대규모 역할, 가입·결제 관리, 장기 보존 자동 정리는 포함하지 않습니다.
8. 이전 주차 목록은 최근 104개를 반환합니다. 더 오래된 데이터는 D1에 남으며 API 목록 페이지네이션을 확장할 수 있습니다.
9. 운영용 설정 값, 실제 D1 database ID, secret 입력, 게스트 검증, deployment는 사용자의 계정 환경에서 남아 있습니다.

## 다음 확장 순서

실제 게스트 검증 → 공용 DB/채널 연결 및 시험 이슈 → Free CPU/쿼리 측정 → 작은 보고 행 묶음과 큐 처리량 개선 → 선택적 Notion OAuth 경로 → 필요한 경우 중첩 본문 요약·장기 결과 페이지네이션을 확장합니다. 회의 자동 결정과 캘린더 등록은 사용자가 별도 요청하기 전 추가하지 않습니다.

## 2026-11-04: Notion 요청 ID 속성 제거

서비스 테스트 53개와 배포·진단 테스트 8개, 타입 검사 및 Worker dry-run 통과. 생성 payload/스키마에서 요청 ID 제거, 5초 abort 적용, 네트워크 오류·408·5xx·잘못된 성공 응답 시 즉시 review, 재클릭/관리자 재시도 시 재생성 방지, 저장된 성공 복구 및 비공개 Discord 결과 갱신을 모의 API로 확인했습니다. 운영 Notion에 시험 이슈를 만들거나 팀 채널에 메시지를 발송한 검증은 아닙니다.
